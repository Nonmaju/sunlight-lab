# sunlight-lab

일조·일조권 사선 검토기. 대지와 건축물 매스를 손으로 입력하면 날짜·시각별 그림자, 동지 일조시간 히트맵, 정북방향 일조 사선(건축법 시행령 제86조) 위반 부위, 건폐율·용적률을 보여준다. 브라우저 전용(서버·GPU·유료 API 없음).

**참고용, 법적 효력 없음.** 이 도구의 결과는 인허가·설계 판단의 근거가 될 수 없다.

## 실행

```bash
npm install      # devDependency: suncalc(테스트 교차검증 전용), three(런타임은 CDN import map으로 로드)
npm test         # node --test (core만 대상)
npm run dev      # python -m http.server 8000 → http://localhost:8000/web/
```

런타임 의존은 Three.js 하나(CDN import map, SRI integrity 적용)이며 SunCalc는 테스트에서만 쓴다. `web/`이 `../core`를 import하므로 저장소 루트를 서빙해야 한다(`web/`만 서빙하면 동작하지 않는다).

## 구조

```
core/   sun, geom, setback, sunhours, coverage, validate, samples   순수 JS(DOM 없음, 노드·브라우저 공용)
web/    index.html, main.js, ui.js, view3d.js, heat.worker.js, style.css
tests/  node --test (+ fixtures/noaa-seoul-2026-12-22.json)
docs/superpowers/specs|plans/
```

## 기능

- 날짜·시각 그림자(표준시 KST / 진태양시 토글), Three.js 3D 뷰
- 동지(상수 `HEAT_DATE` = 2026-12-22) 09~15시 일조 히트맵(날짜 입력과 무관, 최대 연속 / 누적 토글), 지반 격자 + 이웃 건물 외벽 격자, Web Worker 계산
- 정북 사선 검토: 위반 부위 빨간 표시, 허용 사선 면 반투명, 볼륨별 최대 초과 높이
- 변 태그: 인접대지 / 도로·공원 등(폭 입력, 제86조⑥) / 적용제외(제86조②3호)
- 건폐율·용적률(한도 비내장, 사용자가 한도를 입력하면 초과/이내만 표시)
- 평면 편집 + 좌표 직접 입력(대지/볼륨 선택, 검증 통과 시에만 적용)
- 샘플 2종(사선 위반 / 계단형 합격), JSON 내보내기·불러오기(불러올 때 스키마 검증)

## 가정 목록 (UI와 동일)

1. 지표면은 평지로 가정(제119조 평균 수평면 미적용)
2. 옥탑·승강기탑 높이 예외 미적용(전체 높이 산입)
3. 조례값 대신 시행령 하한 기본 적용(1.5m / 10m / 높이의 1/2)
4. 정북 방향 직선 거리로 측정(국토부 해석 미확인)
5. 제86조②1·2호 미모델링, ②3호는 변 태그 「적용제외」로 수동 지정
6. 오목한 대지·여러 변이 겹치는 경우 보수적(과다 표시 가능)
7. 시각 기준(표준시/진태양시) 기본값 미확정 — 토글로 비교
8. 연면적 = 건물 높이 기준 추정치(floor(높이 / 층고), 층고 기본 3.0m). 시행령 제119조①4호는 연면적을 실제 각 층 바닥면적의 합계로, ①9호는 층 구분이 불명확한 건축물만 높이 4m당 1층으로 정하므로 이 추정은 법정 산정이 아님(층고는 설정에서 변경)
9. 참고용, 법적 효력 없음

## 열려 있는 확인 과제

1. 정북 이격의 측정 방향: 법문(제86조①, 시행 2026. 10. 6. 원문 확인)은 "정북 방향으로의 인접 대지경계선으로부터"라고만 적고 측정 방식을 명시하지 않는다. 국토부 질의회신·법제처 해석은 검색으로 찾지 못함. Opus 자문(2026-10-10, 확신도 중간~높음): 정북 직선거리가 법문·허가도서 관행에 부합하므로 유지, 단 경계 수직거리 방식보다 위반을 덜 표시할 수 있어(비보수적) 가정 목록에 고지. 국토부 질의회신 또는 『건축법 해설』 도해로 확인하면 확정.
2. 09~15시가 표준시인지 진태양시인지: 법문(제86조③2호 단서의 "동지를 기준으로 9시에서 15시 사이에 2시간 이상 계속")에 시각 기준이 없다. 진태양시를 요구하는 공식 지침은 못 찾음(일부 분석 시스템 특허 문서가 진태양시를 쓰는 예시만 확인). Opus 자문(확신도 중간, 일본 日影規制의 真太陽時 명시와 판례 계보는 추측 포함): 진태양시가 기준 취지에 맞음(서울 09~15시 진태양시 = 표준시 약 09:30~15:30). 단 근거가 약해 **기본값은 KST로 유지**하고 화면에 환산 구간을 병기한다. 일조감정서·판결문의 "진태양시" 표기 확인 시 기본값 변경 검토. **사용자 결정 대기.**
3. ~~서울시 건축조례의 정북 이격 값이 시행령 하한과 다른지~~ → 확인 완료(2026-10-10): 서울특별시 건축 조례 제35조①(시행 2026. 3. 30., 조례 제10083호)은 높이 10m 이하 1.5m 이상, 10m 초과 높이의 1/2 이상으로 시행령 하한과 동일. 다른 지자체 조례는 미확인(설정에서 변경 가능).
4. 연면적 산정(층수 환산) 방식: 확인함(2026-10-10, 시행령 제119조①). ①4호 "연면적: 하나의 건축물 각 층의 바닥면적의 합계"(용적률 산정 시 지하층·지상층 부속 주차용 등 제외), ①9호 "층의 구분이 명확하지 않은 건축물은 그 건축물의 높이 4미터마다 하나의 층으로 보고 그 층수를 산정". 높이→연면적 환산식은 법에 없으므로 앱의 floor(높이/층고)는 계속 추정치이며 지하층·주차 제외 등은 미반영. 입력이 층별 바닥면적이 아닌 단일 매스인 한 한계로 남김.
5. 동지 날짜: 확인 완료(2026-10-10). 한국천문연구원 월력요항(https://astro.kasi.re.kr/kor/life/post/calendarData?year=2026) 2026년 24절기 표에 동지 12월 22일 5시 50분(KST). 앱의 2026-12-22 사용은 맞다. 다른 연도로 쓰려면 해당 연도 월력요항에서 날짜를 확인해야 한다(상수 HEAT_DATE).
6. 평균 수평면(제119조) 및 옥탑 높이 예외는 미적용(가정 1·2).

## 검증 현황

**자동 테스트:** `node --test` → 79개 중 통과 79, 실패 0, 건너뜀 0 (2026-10-08 실행).

**태양 위치:**
- NOAA Solar Calculator 화면 표시값 3행 fixture 기입됨(출처 https://gml.noaa.gov/grad/solcalc/, 2026-10-07 조회, 서울 37.5665°N 126.978°E, 2026-12-22, +09:00): 09:00 고도 11.57 방위 131.94 / 12:00 28.61 / 172.04 / 15:00 19.65 / 216.23. 허용 오차 0.15°. NOAA 표시 고도는 대기굴절 보정값이며, 기하 고도 + Bennett 굴절이 세 행 모두 0.01° 안에서 일치함을 테스트로 확인했다(잔차 0.03~0.08°는 굴절).
- SunCalc 교차검증: 고도 0.3°, 방위 0.5° 이내.

**히트맵 실측(Worker, 브라우저, 샘플 위반 사례):** gridSpacing 2 → 797점 / 203 ms; gridSpacing 0.5 → 12,077점 / 1310 ms. 설계 단계의 "약 3만 점 ≈ 1초"는 측정하지 않은 추정이었고 이 크기에서는 재현되지 않았다(3만 점은 측정하지 않음).

**SRI·좌표창 확인(내장 브라우저, 2026-10-09):** import map에 integrity를 넣은 상태로 페이지 로드·3D 캔버스 생성 확인. 같은 CDN 파일을 integrity 옵션으로 fetch하면 올바른 sha384는 통과, 틀린 값은 차단됨. 좌표 입력창에서 볼륨 N1을 선택한 채 다른 볼륨 A를 삭제해도 선택(N1)과 텍스트 유지.

**샘플 히트맵 비교(테스트, 이웃 벽 108점 평균 연속 일조):** 위반 샘플 약 143분(120분 이상 78점) < 합격 샘플 약 169분(86점).

**최종 보강 라운드 화면 확인(내장 브라우저, 실제 실행):** 동지 상수 범례 문구, 날짜를 여름으로 바꿔도 히트맵 재계산 없음(Worker 시작 횟수 불변; 점별 값 자체는 직접 비교하지 않음), 좌표 직접 입력(유효 5각형 적용·변 태그 유지/초기화, 점 2개·자기교차·숫자 아님은 거부), 한도 60%→이내 / 40%→초과 / 빈칸→표시 없음(위반 샘플 51.3%), (+500,+300) 이동 샘플 JSON 불러오기 후 3D 그림자 렌더, Worker 오류 시뮬레이션 후 동일 입력 재시도(성공), 두 샘플(256.7% / 위반 5.00m, 238.0% / 위반 없음).

**화면 확인(내장 브라우저, 이전 라운드):**
- 확인함: 페이지 로드, 3D 뷰 그림자 렌더링, 1400×900 폭에서 3열 레이아웃, 위반 샘플 12:00 KST에서 그림자 방향의 코어 계산과의 대략 일치(아래).
- 그림자-코어 일치(수동 1회): 태양 고도 28.58°/방위 172.04°. 코어 `isLit`: 박스 A 북쪽 지면 [10,28], [10,31], [10,40] 모두 그늘, 이웃 남쪽 벽 [10,32.98]은 높이 11 그늘 / 11.5 양지(손계산 경계 약 11.2m와 일치). 3D 뷰에서는 A의 그림자가 북서쪽(화면 왼쪽 뒤)으로 길게 뻗어 이웃 건물 남측 지면·벽 아래쪽을 덮는 것이 보여 방향은 일치. 벽의 11.2m 경계(이웃 높이 12m 중 상단 약 0.8m)는 화면에서 육안으로 분해되지 않아 그 부분은 **육안 미확인**.
- 미확인: 입력 오류 시 3D 뷰 정지 동작, 실제 파일 선택창을 통한 JSON 불러오기, 히트맵 범례 스크린샷, 궤도(orbit) 컨트롤, 사선/히트맵 모드의 시각적 정확성 전반.

## 알려진 한계

- 사선: 도로 폭 이동은 정북으로 적용(경계가 정북에 수직인 변에서만 정확, 기울어진 변은 경계가 실제보다 가까워져 보수적). 가까운 변이 적용제외이고 먼 변이 적용 대상일 때 변들의 합집합이 과다 표시할 수 있음(보수적).
- 일조: 10분 간격 샘플링이라 10분보다 짧은 그림자는 놓칠 수 있음. 동·서 외곽선 위의 점에 정남북 태양 광선이 걸리면 반개구간 판정(한 샘플 아티팩트). `rayHit`(반개구간)과 `rayCrossings`(교차 헬퍼)는 정의가 다름(내부 사항).
- 입력: `validateState`의 좌표 상한은 임의값 ±100000m. 비볼록 대지의 홈을 가로지르되 경계와 정확히 만나는 꼭짓점만 있는 건물은 통과할 수 있음.
- 3D: WebGL 초기화 실패 시 안내 문구만 표시하고 평면도는 유지(코드 경로만 구현, 실제 WebGL 없는 환경에서는 실행해 보지 못함).
- 히트맵: 항상 동지 상수 날짜로 계산(그림자 뷰의 날짜와 독립). 날짜 상수는 KASI 월력요항으로 확인함(2026-12-22). 필로티(z0>0.05) 아래 지반점은 포함한다.
- 입력: 불러온 JSON의 중복 id, `edges: []`는 거부.
- 테스트: 초기 단계(sun/geom/setback)의 사소한 테스트 공백이 일부 남아 있음(전체 브랜치 검토 보고 참조).
- 배포: `../core` import 때문에 어떤 배포든 저장소 루트를 서빙해야 함.
