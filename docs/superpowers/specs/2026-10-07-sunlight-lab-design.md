## 1. 목적과 제약

브라우저에서만 동작하는 포트폴리오 데모. 대지와 건축물 매스를 손으로 입력하면 다음을 보여준다.

1. 날짜·시각별 그림자
2. 동지 일조시간 히트맵
3. 정북방향 일조 사선(건축법 시행령 제86조①) 위반 부위
4. 건폐율·용적률 계산값

고정 제약: 비용 0, GPU 가정 없음, 정적 사이트(서버 없음), 유료 API 없음, 외부 지형·건물 API 없음(사용자 입력 매스만), 일반 HTML/JS 모듈(빌드 스텝 없음), 로직 테스트는 `node --test`. **배포·공개는 사용자 명시 승인 후에만.** 팀 Auto-BIM 저장소 코드는 재사용하지 않는다.

## 2. 법적 근거 (law.go.kr 원문, 2026-10-07 조회, 건축법 시행령 시행 2026. 10. 6.)

### 제86조(일조 등의 확보를 위한 건축물의 높이 제한) 발췌

① 전용주거지역이나 일반주거지역에서 건축물을 건축하는 경우에는 법 제61조제1항에 따라 건축물의 각 부분을 정북(正北) 방향으로의 인접 대지경계선으로부터 다음 각 호의 범위에서 건축조례로 정하는 거리 이상을 띄어 건축하여야 한다.
 1. 높이 10미터 이하인 부분: 인접 대지경계선으로부터 1.5미터 이상
 2. 높이 10미터를 초과하는 부분: 인접 대지경계선으로부터 해당 건축물 각 부분 높이의 2분의 1 이상

② 다음 각 호의 어느 하나에 해당하는 경우에는 제1항을 적용하지 아니한다.
 1. (지구단위계획구역·경관지구·중점경관관리구역·특별가로구역·허가권자 지정 구역 안의 대지 상호간에 건축하는 건축물로서 해당 대지가 너비 20미터 이상의 도로에 접한 경우)
 2. 건축협정구역 안에서 대지 상호간에 건축하는 건축물(건축협정에 일정 거리 이상 띄어 건축하는 내용이 포함된 경우만 해당)
 3. 건축물의 정북 방향의 인접 대지가 전용주거지역이나 일반주거지역이 아닌 용도지역에 해당하는 경우

⑥ 제1항부터 제5항까지를 적용할 때 건축물을 건축하려는 대지와 다른 대지 사이에 공원(일부 예외), 도로, 철도, 하천, 광장, 공공공지, 녹지, 유수지, 자동차 전용도로, 유원지가 있는 경우에는 그 반대편의 대지경계선(공동주택은 인접 대지경계선과 그 반대편 대지경계선의 중심선)을 인접 대지경계선으로 한다.

참고(v1 범위 밖, 기록용): ③2호 단서 "그 대지의 모든 세대가 동지(冬至)를 기준으로 9시에서 15시 사이에 2시간 이상을 계속하여 일조(日照)를 확보할 수 있는 거리"는 공동주택 동 간 거리의 대체 기준이다. 이 앱의 "연속 2시간" 기준선은 이 표현에서 가져온 **참고 기준**이며 정북 사선의 합격 기준이 아니다.

**주의:** 1.5m와 높이의 1/2은 "건축조례로 정하는 범위"의 하한이다. 실제 값은 지자체 조례에 따라 다를 수 있다(앱은 파라미터로 받고 기본값은 시행령 하한).

### 제119조 제1항 제5호 나목(높이 산정, 법 제61조 관련) 발췌

"법 제61조에 따른 건축물 높이를 산정할 때 건축물 대지의 지표면과 인접 대지의 지표면 간에 고저차가 있는 경우에는 그 지표면의 평균 수평면을 지표면으로 본다."
같은 호 다목·라목에는 옥상 승강기탑·계단탑·옥탑 등의 높이 산입 예외가 있다.

→ v1은 평지(z=0)로 가정하고 옥탑 예외는 적용하지 않는다(5절 가정 목록).

## 5. 계산 방식

### 5.1 정북 사선 (`setback`)

요구 이격 `d(z) = lowD (z ≤ lowH)`, `z × ratio (z > lowH)`, 기본값 1.5m / 10m / 0.5.

판정(정의): 높이 z의 점 p에 대해, p에서 정북 방향 광선이 비적용 경계(`적용제외` 제외, `도로·공원` 변은 폭만큼 정북으로 이동)를 처음 만나는 지점까지의 거리가 `d(z)` 미만이면 위반.

구현: `allowed(z) = 대지 − ∪(비적용 변을 정북 방향으로 d(z)만큼 남쪽으로 쓸어낸 영역)`을 2D 다각형 클리핑으로 구한다. 각 볼륨을 z=10m, 상단, 10m 위로 0.5m 간격으로 슬라이스해 `allowed(z)` 밖에 나온 조각을 위반 부위로 반환한다. 3D 뷰에서 빨간색으로 표시하고 `allowed` 사선 면을 반투명으로 겹친다.

### 5.2 일조시간 (`sunhours`)

- 측정점: 지반 격자(대지+주변), `neighbor` 볼륨의 외벽 격자(정남·동·서향 위주). 격자 간격은 사용자 조절 가능, 현재 간격을 화면에 표시.
- 동지 09:00~15:00을 10분 간격으로 샘플링, 각 점에서 태양 방향 광선을 쏴 모든 볼륨과의 교차를 검사(2D 광선-변 교차 + 높이 범위 검사, 바운딩 박스 사전 배제).
- 점마다 `{ 최대 연속, 누적 }` 모두 저장, 화면에서 토글. 연속 2시간 기준선은 "참고 기준" 표기.
- 전이 시각(일조↔음영)은 이분법으로 약 1초 정밀도까지 보정해 샘플링 양자화 오차(최대 ±10분)를 제거한다. 샘플 경계 처리 규칙은 구현 시 문서에 고정한다.
- 처리 속도는 Opus 추정(약 3만 점 × 37스텝 × 볼륨 10개 규모 ≈ 1초, **미측정**). 구현 후 실측하고, 느리면 격자 해상도를 낮춘다.

### 5.3 그림자 뷰

Three.js는 코어의 태양 벡터로 조명 방향을 정하고, 그림자맵은 표시용이다. 계산 결과와의 일치는 회귀 테스트로 확인한다.

### 5.4 건폐율·용적률 (`coverage`)

건축면적 = `mine` 볼륨 바닥 다각형의 지상 투영 합집합 면적. 연면적 = 볼륨별 층수 환산 면적 합(층수 환산 방식은 확인 과제 4). 한도는 앱이 내장하지 않고, 사용자가 입력하면 비교만 한다(기본 빈칸).

### 5.5 UI에 항상 표시할 가정 목록

1. 지표면은 평지로 가정(제119조 평균 수평면 미적용)
2. 옥탑·승강기탑 높이 예외 미적용(전체 높이 산입)
3. 조례값 대신 시행령 하한 기본 적용
4. 정북 방향 직선 거리로 측정(국토부 해석 미확인, 확인 과제 1)
5. 제86조②1·2호 미모델링
6. 오목한 대지는 보수적으로 판정
7. 시각 기준(표준시/진태양시) 기본값 미확정(확인 과제 2)
8. 연면적 층수 환산은 임시 규칙: floor(높이 / `floorHeight`), 층고 기본 3.0m(확인 과제 4)
9. 참고용, 법적 효력 없음

## 6. 화면과 흐름

데스크톱 우선, 모바일은 보기 위주. 3영역:

- **왼쪽(입력):** 상단 `샘플: 사선 위반 사례` / `샘플: 계단형 합격 사례` 버튼, 대지·볼륨 목록, 설정.
- **가운데(뷰):** 탭 전환 — **평면 편집**(2D 캔버스: 꼭짓점 클릭·드래그, 좌표 직접 입력, 변 클릭으로 태그 지정, 변 색상으로 태그 구분, 정북 화살표 회전) / **3D 뷰**(모드: 그림자 슬라이더 + 시각 기준 토글, 일조 히트맵, 사선 검토).
- **오른쪽(결과):** 건폐율·용적률, 볼륨별 위반 여부와 최대 초과 높이, 히트맵 범례, 접이식 가정 목록, 고정 문구.

볼륨마다 바닥 다각형, z0, h, 역할(`내 건물`/`이웃 건물`) 입력. 직사각형 볼륨 추가 버튼 제공.

실행: 입력 변경 시 사선 검사는 즉시, 일조 히트맵은 Web Worker에서 진행률 표시와 함께 계산(입력이 바뀌면 이전 작업 취소). 상태 객체 하나를 뷰가 그리기만 한다. v1 저장·공유는 JSON 내보내기·불러오기(URL 해시 공유는 선택 과제).

### 샘플 2종 (같은 직사각형 대지, 정북 위)

1. **사선 위반 사례:** 5층(15 m) 단순 박스. 위반 부위가 빨갛게 표시되고 이웃 건물 벽면 일조가 나쁨.
2. **사선 맞춤 계단형 합격 사례:** 사선에 맞춰 후퇴한 단상 매스. 위반 0, 일조 개선.

정북 인접 대지에 `neighbor` 저층 건물을 두어 두 사례의 히트맵 차이를 바로 볼 수 있게 한다. 두 샘플은 버튼 하나로 전환한다.

## 7. 검증

- **태양 위치:** 직접 구현한 NOAA 알고리즘 결과를 (a) SunCalc, (b) NOAA Solar Calculator·KASI 값 몇 개(출처 URL과 조회일을 fixture에 기록)와 비교. **실제 사용 허용 오차:** NOAA fixture 0.15°, SunCalc 교차검증 고도 0.3° / 방위 0.5°(당초 0.1°에서 조정). SunCalc 방위 규약(남쪽 기준, 서쪽 양수, 라디안)은 변환해 비교했다. NOAA 표시 고도는 대기굴절 보정값이다: 우리의 기하 고도가 NOAA보다 0.03~0.08° 낮은 잔차는 Bennett 굴절식(R[분] = 1/tan((h + 7.31/(h + 4.4))°))을 더하면 0.01° 안에서 일치한다(`tests/sun.test.js`에서 확인; 방위는 굴절과 무관). 서울 경도 126.98 사용.
- **사선 기하:** 손계산 케이스 — 정북이 위인 직사각형에서 높이 12m → 이격 6m, 정북 30° 회전, 높이 정확히 10m(1.5m↔5m 경계), L자 대지, 도로 변 이동(폭 w), 광선이 동쪽 변으로 나가는 경우.
- **일조시간:** 동서로 무한히 긴 벽과 박스 케이스로 전이 시각을 손계산해 비교.
- **건폐율·용적률:** 직사각형 합집합, 겹치는 볼륨.
- **그림자-계산 일치:** Three.js 렌더와 코어를 노드에서 자동 비교할 수 없으므로(WebGL 필요) (i) 공유 좌표 규약을 고정하는 노드 테스트(`sunDirection`의 방위 0°가 `northVec(angle)`, 180°가 그 반대; angle 0/30/-45)와 (ii) 문서화된 수동 확인(README 검증 현황)으로 대체한다.
- **화면(Three.js·입력 UI):** 내장 브라우저로 직접 확인. 확인하지 못한 부분은 완료 보고에 "미확인"으로 명시.

## 8. 오류 처리 (입력 신뢰 경계만)

자기교차 다각형, 꼭짓점 3개 미만, 높이 ≤ 0, 대지 밖 볼륨은 입력 단계에서 막거나 경고하고 계산하지 않는다.

## 9. 확인 과제 (구현 전/중 해결)

1. **정북 방향 이격의 측정 방향:** 정북 직선 거리 vs 경계선 수직 거리. 국토교통부 질의회신 또는 서울시 건축조례 해설로 확인. (2026-10-10: 법문에 측정 방식 명시 없음 확인, 회신 문서는 못 찾음. Opus 자문으로 정북 직선 거리 유지 + 비보수적 가정 고지)
2. **09~15시가 표준시인지 진태양시인지:** 서울은 두 값의 차가 약 30분이라 2시간 판정이 뒤집힐 수 있음. 2026-10-10: 법문에 시각 기준 없음 확인, 공식 지침 못 찾음. Opus는 진태양시 권고(확신도 중간)이나 기본값은 KST 유지·토글·환산 구간 병기, 기본값 변경은 사용자 결정 대기.
3. **서울시 건축조례의 정북 이격 값:** 시행령 하한과 다른지.
4. **연면적 산정(층수 환산) 방식.**
5. **동지 날짜:** 2026-12-22를 `HEAT_DATE` 상수로 사용 중 — KASI 월력요항으로 확인 필요.
6. **평균 수평면(제119조)·옥탑 높이 예외 미적용:** 평지 가정과 전체 높이 산입(가정 목록 1·2).

## 10. 설계 근거 메모

- 접근안 A(순수 JS 코어 + CPU 광선 검사, Three.js는 표시 전용) 채택. 대안 B(그림자맵 샘플링)는 GPU/DOM 필요·노드 테스트 불가로 기각, 대안 C(프리즘 투영 합집합)는 벽면 격자와 비볼록 형상이 까다로워 보류. Opus 5.5 자문(2026-10-07) 반영.
- 일정: 초기 브레인스토밍의 Opus 추정은 3~4주(미측정). v1 범위를 정북 사선으로 좁혔으므로 플랜 작성 후 단계별로 재추정.

## 11. 구현 중 변경점

- `core/validate.js`에 `validateState`(JSON 불러오기 스키마 검증) 추가: 불러온 파일의 구조 오류·HTML 주입·0/NaN 격자 간격으로 인한 Worker 정지를 막기 위함(입력 신뢰 경계, 8절 확장).
- `core/geom.js`에 `rayCrossings`(정점 접촉에서 짝수/홀수가 맞는 교차 목록)와 `pointOnBoundary` 추가: 반개구간 `rayHit`은 정점 스침을 한 번만 세어 `isLit`의 구간 짝짓기에 쓸 수 없고, 반개구간 `pointInPolygon`은 동·북 경계 위 점을 밖으로 판정하기 때문.
- 포함 판정을 경계 포함으로 변경(`validate`의 볼륨-대지 포함 검사): 대지 경계에 접한 건물이 오류로 거부되던 문제 수정.
- `isLit`에서 측정점을 태양 쪽으로 1e-6 이동: 외벽·건물 경계 위의 점이 자기 볼륨에 가려져 양지로 잘못 판정되던 문제 방지.
- 히트맵 Worker 수명 관리(입력 변경 시 즉시 종료·재시작, 오류 경로 초기화, `onerror`): 낡은 결과 표시와 "계산 중" 고착 방지. 속도 실측은 797점 203 ms(간격 2) / 12,077점 1310 ms(간격 0.5)이며 5.2절의 "3만 점 ≈ 1초" 추정은 재현되지 않았다.
- UI는 숫자 입력이 비유한·비양수일 때 되돌린다(`gridSpacing ≥ 0.5`, `floorHeight ≥ 2`, `z0 ≥ 0`, `h > 0`): Worker 무한 루프 방지.
- 최종 보강 라운드(전체 브랜치 검토 반영), 통제자 결정 R9~R11:
  - R9: 히트맵은 설정 날짜가 아니라 상수 `HEAT_DATE = '2026-12-22'`(동지)로만 계산한다. 그림자 뷰는 `settings.date`를 그대로 쓴다. 날짜가 틀렸다면 상수 한 줄만 바꾼다.
  - R10: 렌더-코어 자동 비교는 노드에서 불가능하므로 7절의 회귀 테스트를 좌표 규약 고정 테스트 + 수동 확인으로 대체했다.
  - R11: 스펙 6절의 좌표 직접 입력(대지/볼륨 선택, 복제 상태에서 `validate` 통과 시에만 적용; 대지 꼭짓점 수가 바뀌면 변 태그 초기화)과 5.4절의 건폐율·용적률 한도 입력(UI 전용 `state.limits`, 내보내기 제외, 한도 내장 없음)을 최소 구현했다.
  - 코어: `maxExcess`는 공중에 뜬 볼륨에서 `상단 − max(허용 높이, 볼륨 z0)`(볼륨 자신의 두께 이내), `profile`의 `Lmax` 하한 클램프, `wallGrid`의 길이 0 변 건너뛰기, `validate`의 연속 중복 꼭짓점 오류.
  - 웹: 3D 조명 목표·그림자 카메라·궤도 중심을 장면 bbox에서 유도(원점 밖 대지에서도 그림자 렌더), 히트맵 Worker 오류 후 상태 초기화(진행/오류 알림이 재요청하지 않음), `ui.js` 로드 실패 메시지.
